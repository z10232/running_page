# Keep 新增跑步同步到高驰

每天北京时间 08:00，`Run Data Sync` 先同步 Keep 到个人主页，随后独立把新增跑步上传到高驰中国训练平台。高驰上传失败会使该任务显示失败；主页仍独立发布。

在 GitHub 仓库的 `Settings → Secrets and variables → Actions` 保存：

| Secret / 环境变量 | 内容 |
| --- | --- |
| `KEEP_MOBILE` | Keep 国内手机号 |
| `KEEP_PASSWORD` | Keep 登录密码 |
| `COROS_ACCOUNT` | 高驰中国区手机号 |
| `COROS_PASSWORD` | 高驰登录密码 |

程序从环境变量读取凭证。账号需要支持手机号和密码登录；要求额外验证时，任务停止并提示在训练平台完成验证。日志只显示处理数量和安全错误说明。

## 新增记录与重试

`activities/keep2coros.json` 分别保存历史排除列表、高驰已确认成功的回执，以及等待确认的导入任务编号。2026 年 10 月 27 日，按用户授权清空历史排除列表，补传全部历史跑步；此前已成功的记录继续跳过。补传完成后，日常任务只处理新增或尚未成功的记录，失败记录会在下一次任务重试。

文件提交成功后，还要等待高驰完成导入才记录成功。任务超过本轮等待时间时保留编号，下次继续核对；如已在高驰找到同一开始时间和用时的跑步，则记录已有活动，避免重新导入。本地清单缺失或损坏时停止上传，恢复清单后再运行。已保存的任务如果不再出现在高驰最近任务列表中，会继续等待核对，需检查高驰活动和 Actions 日志后处理。

跑步以 FIT 文件传输，使用 Keep 官方距离、运动用时、累计爬升和实际提供的轨迹、海拔、心率。缺失的测量值保持缺失。FIT 标准的累计爬升精度为整数米。临时文件仅在内存中构建，不将账号、令牌或原始详情写入同步清单。

## 手动运行与单条验证

在 Actions 打开 `Run Data Sync`，点击 `Run workflow`。日常运行将 `coros_sample_id` 留空。

获得明确授权后，可在 `coros_sample_id` 填入一条 Keep 数字 ID 来验证历史活动。这次只处理该条，不补传其他历史记录；成功后也会写入清单，再次运行会跳过它。

本地运行使用相同的环境变量：

```sh
python run_page/keep_to_coros_sync.py
```

高驰接口沿用其当前网页的中国区登录、临时文件存储和异步导入流程。平台变更接口时可能需要调整客户端，可从 Actions 日志查看同步结果。
